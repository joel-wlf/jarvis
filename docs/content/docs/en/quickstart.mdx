## 1. Install

There are three ways. For most people the first is the easiest: no terminal, no commands.

### Ready-made Raspberry Pi image (recommended)

You need a Raspberry Pi 4 or 5 (4 GB or more), a microSD card of 32 GB or more and a computer with a card reader. Hardware tips are in the [Raspberry Pi guide](./raspberry-pi.mdx).

1. Download the image file `jarvis-…-arm64.img.xz` from the [latest release](https://github.com/joel-wlf/jarvis/releases/latest).
2. Install the [Raspberry Pi Imager](https://www.raspberrypi.com/software/) and start it.
3. Choose your Pi as the device, **"Use custom"** at the very bottom of the operating systems, then the downloaded file. Choose your SD card.
4. **With a network cable** there is nothing else to set. **With Wi-Fi**, say yes when the Imager asks whether to apply OS customisation and enter your Wi-Fi name and password there. Leave the host name at `jarvis` or empty.
5. Let it write, put the card into the Pi, power on.
6. On your phone or computer in the same network open **[http://jarvis.local](http://jarvis.local)**.

On the first start Jarvis downloads its programs, usually in 5 to 15 minutes. Until then the page says "Jarvis is getting ready" and reloads by itself.

<Callout title="jarvis.local does not open?">
Older Android devices and some routers do not know `.local` addresses. Look for the device **jarvis** in your router's device list and open its address, for example `http://192.168.1.42`.
</Callout>

Advanced users can add the image list to the Imager directly: `rpi-imager --repo https://github.com/joel-wlf/jarvis/releases/latest/download/rpi-imager.json`. Jarvis then shows up in the menu, and the Imager always offers its settings.

### With the installer on an existing Linux machine

For any 64-bit Linux machine where you already have a terminal:

<InstallCommand />

The script checks Docker (and installs it on Debian and Ubuntu after asking), pulls the prebuilt images and prints the address at the end, usually `http://<address-of-the-machine>:8081`.

### With Docker Compose

```bash
git clone https://github.com/joel-wlf/jarvis.git ~/jarvis && cd ~/jarvis
docker compose up -d admin app-web
```

Then open `http://<address-of-the-machine>:8081`.

## 2. Run the setup assistant

The assistant in the browser takes you through seven steps. You can stop at any time and continue later.

1. **Name** of your assistant.
2. **Password** (at least 15 characters). Whoever opens the page first sets it, so set Jarvis up right after it starts.
3. **Source**: confirm the notes about the WhatsApp connection. Jarvis now generates all internal passwords and starts the services.
4. **Link WhatsApp**, see below.
5. **AI**: the easiest is **"Sign in with OpenRouter"**. Sign in to OpenRouter or create an account there, add some credit (5 $ is enough to start) and you come back automatically. There is no key to copy. Alternatively paste an OpenAI key. This is also where you choose which chats never go to the AI.
6. **Remote access**: home network only, a Cloudflare tunnel, or your own address. Home network only is perfectly fine to start.
7. **Done**: QR code for the app and the address for Claude.

<Callout type="warn">
With an AI provider, message content is sent to that provider. Excluded chats and redaction limit what leaves your device. See the [disclaimer](./disclaimer.mdx#ai-provider).
</Callout>

<Callout title="OpenRouter or OpenAI?">
With OpenRouter, search runs on your device and voice messages stay without text, because OpenRouter offers no transcription. With an OpenAI key both go through OpenAI. You can switch later under System → Settings.
</Callout>

## 3. Link WhatsApp

<Callout type="warn">
This uses an unofficial connection. WhatsApp can restrict or ban accounts that use unofficial clients, so consider a secondary number. See the [disclaimer](./disclaimer.mdx).
</Callout>

The assistant shows a **QR code** in the browser, or a **pairing code** if you enter your phone number.

On your phone: WhatsApp → Settings → Linked devices → Link a device → scan.

Afterwards the phone sends your history in batches. This can take several minutes. Keep the phone online with WhatsApp open meanwhile. How much history you get is decided by WhatsApp.

## 4. Pair the app

Open the web app at the same address, or install the Jarvis app. On the connect screen you have two ways:

- **Scan a code.** The assistant's last step (and later System → Devices) shows a QR code. Point the app's camera at it.
- **Address and password.** Enter the address and the password you chose.

Details are in [The app](./app.mdx).

## 5. Connect Claude

With remote access, add your public address as a custom connector in Claude. See [Connect Claude](./connect-claude.mdx).

## Afterwards: updates and state

- **Updates arrive by themselves.** Every night at 4 o'clock Jarvis loads new versions and restarts only the parts that changed. If the new state does not run cleanly, the old one comes back. Turn it off or change the hour under System → Settings → Interface.
- **The state is under System.** When all is well it says "Everything runs". Otherwise you see in plain words what is wrong, for example "WhatsApp was logged out", with the button that fixes it.

## For advanced users: check from the terminal

```bash
docker compose ps
docker compose exec postgres psql -U jarvis -c "select count(*) from messages"
```

The number grows while the history is imported. Without the web interface, `docker compose logs -f wa-ingest` prints the WhatsApp QR code in the log.
